# AUDIT-DRIVEN-TEST-GEN.md — Generating Property Tests from the Audit

The audit's per-site write-ups describe invariants. Each invariant is testable. The audit's work doesn't end at classification — the audit MULTIPLIES the project's test surface.

The test-generator subagent reads (A) and (C) site write-ups + generates property tests that exercise the named invariants.

---

## What gets generated

### For (A) sites

A property test that ASSERTS the obligation: any input the (A) site is called with satisfies the obligation.

```rust
// audit-generated test for site-0142 (A): libc::open(path, ...) requires CStr
proptest! {
    #[test]
    fn site_0142_obligation_check(path_str in proptest::collection::vec(any::<u8>(), 1..=4096)) {
        // Construct a CStr from the proptest input
        if let Ok(c_str) = std::ffi::CString::new(path_str) {
            // The pub API mycrate::open_safe takes a &CStr; the invariant is
            // satisfied by construction. Just verify the call doesn't panic.
            let _ = mycrate::open_safe(c_str.as_c_str(), libc::O_RDONLY);
        }
        // If CString::new failed, the input had an interior null — that's
        // exactly the invariant the type system enforces. No call needed.
    }
}
```

The test EXPLICITLY exercises the type-level invariant; if it ever breaks, the test fails before runtime UB.

### For (C) sites

A property test that compares the safe rewrite against the unsafe original:

```rust
// audit-generated test for site-0203 (C): u32::from_le_bytes replaces transmute
proptest! {
    #[test]
    fn site_0203_equivalence(bytes in proptest::array::uniform4(any::<u8>())) {
        let unsafe_result = original::parse_u32_le(&bytes);
        let safe_result = rewritten::parse_u32_le(&bytes);
        prop_assert_eq!(unsafe_result, safe_result);
    }
}
```

This is the standard equivalence test from [10-POINTER-MIGRATIONS.md § Equivalence-proving patterns](../patterns/10-POINTER-MIGRATIONS.md), but auto-generated.

### For (B) sites

A property test that verifies the safe-only path is equivalent on every input the perf-path accepts:

```rust
// audit-generated test for site-0421 (B): SIMD vs safe-only
proptest! {
    #[test]
    fn site_0421_safe_only_equivalence(bytes in proptest::collection::vec(any::<u8>(), 0..=4096)) {
        #[cfg(not(feature = "safe-only"))]
        let perf_result = mycrate::count_byte_simd(&bytes, b'a');
        #[cfg(feature = "safe-only")]
        let perf_result = mycrate::count_byte_safe(&bytes, b'a');

        // Both feature combinations must produce the same result.
        let safe_result = mycrate::count_byte_safe(&bytes, b'a');
        prop_assert_eq!(perf_result, safe_result);
    }
}
```

## How invariants become tests

The test-generator reads the per-site write-up's `## 2. Invariants` section, parses each "sound IFF [condition]" claim, and translates [condition] into a proptest strategy.

Translation table:

| Invariant claim | Proptest strategy |
|-----------------|-------------------|
| "input is non-null" | `prop::option::weighted(0.99, any::<&[u8]>())` then filter `is_some()` |
| "input length ≥ N" | `prop::collection::vec(any::<u8>(), N..)` |
| "input is null-terminated" | `prop::strategy::Just(CString::new(s)?)` |
| "value is in 0..M" | `0..M::<u32>` |
| "fd is open" | construct via tempfile or pipe |
| "ptr is from arena X" | `arena.alloc(arbitrary())` |

The translation table grows as the audit encounters new invariant kinds.

## Where the tests live

```
<project>/
  tests/
    audit_generated/      <-- new directory
      site_0142.rs
      site_0203.rs
      site_0421.rs
      ...
      MANIFEST.md         <-- which test maps to which audit entry
```

The MANIFEST cross-references: site-id → test file → audit/plans/site-<id>.md.

CI runs `cargo test --test 'audit_generated::*'`.

---

## Manifest format

`tests/audit_generated/MANIFEST.md`:

```markdown
# Audit-generated tests

| Site | Class | Test file | What it exercises |
|------|-------|-----------|--------------------|
| site-0142 | (A) | tests/audit_generated/site_0142.rs | libc::open obligation: path is null-terminated (CStr) |
| site-0203 | (C) | tests/audit_generated/site_0203.rs | u32::from_le_bytes ≡ transmute (equivalence) |
| site-0421 | (B) | tests/audit_generated/site_0421.rs | SIMD ≡ safe-only on canonical inputs |
| ... |

## Provenance
Auto-generated by audit-driven-test-gen on <date>.
Update by rerunning `subagents/test-generator.md` against `<audit-dir>`; this skill does not ship a standalone test-generator script.
```

The manifest is regenerated each time; manual edits get overwritten. To customize a test, EXTEND it (don't modify the generated one).

---

## When NOT to auto-generate

Some invariants can't be translated to proptest strategies:

- "Caller holds a lock on X." (Stateful; needs custom fixture.)
- "Pointer is from caller's stack frame." (Untypeable.)
- "This is reached only on Linux with kernel ≥ 5.10." (Environment-dependent.)
- "FFI peer doesn't write to this region during the call." (Race condition; needs loom or shuttle.)

For these, the test-generator emits a SKELETON test with TODO markers and a comment explaining why auto-generation isn't sufficient. The user / a refactor-planner agent fills it in.

---

## Compound effect

Per audit (200 sites), the test-generator produces:

- ~50 obligation-check tests for (A) sites.
- ~150 equivalence tests for (C) sites (depends on how many graduated from (B)).
- ~20 safe-only-equivalence tests for (B) sites.

The project's test suite GROWS by ~220 tests as a side effect of the audit. Each test was justified by an audit decision; together they're a regression suite for soundness.

## CI integration

```yaml
# In gh-actions-auditor.yml.template, add:
audit-generated-tests:
  name: audit-generated tests
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@v4
    - run: cargo test --test 'audit_generated::*'
```

The audit-generated tests run on every PR, same as regular tests.

---

## Test-generator subagent

[subagents/test-generator.md](../../subagents/test-generator.md):

1. Reads the per-site write-up.
2. Extracts each invariant from `## 2. Invariants`.
3. Maps to a proptest strategy (per the translation table).
4. Emits `tests/audit_generated/site_<id>.rs`.
5. Updates the MANIFEST.

---

## Acceptance signal

Audit-driven test generation is healthy when:

1. Every (A) site has an obligation-check test.
2. Every (C) site has an equivalence test (already required by polish-bar).
3. Every (B) site has a safe-only-equivalence test.
4. The MANIFEST is current.
5. `cargo test --test 'audit_generated::*'` is green.

The audit's value compounds via tests as well as documentation.
