# Bundle Format Specification (v1.0)

The recovery bundle is a self-contained, self-describing artifact. Tools (other than this skill) can consume it. This spec defines the format precisely so future tooling has a stable contract.

---

## Top-level layout

```
<project-parent>/<basename>-stash-archive-<YYYY-MM-DD>/
├── README.md                         (human-readable; recovery recipes)
├── index.tsv                         (machine-readable; one row per stash)
├── meta/
│   ├── 000.txt
│   ├── 001.txt
│   └── ...
├── diffs/
│   ├── 000.diff                      (output of `git stash show -p --binary <index.tsv:sha>`)
│   ├── 001.diff
│   └── ...
└── stashed-untracked/                (only when stash had `-u`)
    ├── 000/
    │   └── path/to/untracked-file.ext
    └── ...
```

The bundle directory's name is `<basename>-stash-archive-<YYYY-MM-DD>` where:
- `<basename>` is the basename of the project root (`/data/projects/foo` → `foo`)
- `<YYYY-MM-DD>` is the UTC date of the bundle creation

The bundle lives **outside** the repo (in the parent directory) so it survives `git clean -fdx` and doesn't pollute `git status`.

---

## `index.tsv`

Tab-separated, one row per stash. Header:

```
n  ref  sha  parent_sha  date  author  message  files  insertions  deletions  has_untracked  bundle_artifacts
```

| Column | Type | Description |
|--------|------|-------------|
| `n` | int | Zero-based stash index at bundle creation time |
| `ref` | string | The stash ref (`stash@{N}`) at bundle creation time |
| `sha` | string | Full commit SHA of the stash |
| `parent_sha` | string | Stash commit's first parent, normally HEAD at stash creation time |
| `date` | ISO 8601 | Committer date |
| `author` | string | Committer name |
| `message` | string | Stash message with git's "On <branch>:" / "WIP on..." prefix stripped |
| `files` | int | File count from `git stash show --stat` |
| `insertions` | int | Insertion count |
| `deletions` | int | Deletion count |
| `has_untracked` | bool | `true` if stash was made with `-u` |
| `bundle_artifacts` | csv | Comma-separated list of bundle paths for this stash |

Example row:
```
34	stash@{34}	8a3d2c9...	7f3a1b8...	2026-04-29 14:22:11	agent-cc-12	wip-BACK-1742-mysql-ok	1	2	0	false	diffs/034.diff,meta/034.txt,refs/stash-backup/034
```

---

## `meta/<NNN>.txt`

Plain text, one key=value per line. Keys (all required):

```
sha=<full sha>
parent_sha=<full parent sha>
date=<ISO 8601 committer date>
author=<author name>
has_untracked=<true|false>
message=<stash message; prefix-stripped>
```

The `message` may contain spaces; everything after `message=` is the value (no escaping; line-terminated).

---

## `diffs/<NNN>.diff`

The verbatim output captured at bundle-build time from the stable stash identity in `index.tsv`:
```bash
git stash show -p --binary <sha>
```

This is **NOT** `git format-patch -1 stash@{N}`. A stash is a merge commit, and format-patch is not the stash-show recovery diff.

The diff format:
- Standard unified diff
- Includes `diff --git a/PATH b/PATH` headers
- Includes `index <old>..<new>` lines
- Includes `--- a/PATH` and `+++ b/PATH` markers for normal text patches
- Includes `GIT binary patch` payloads for tracked binary files; pure binary modifications may have `diff --git` + `index` + `GIT binary patch` without `---`/`+++` markers
- For new files: `new file mode <mode>` line; for deleted files: `deleted file mode <mode>`

The diff applies to a working tree at the stash's PARENT commit. With `git apply --3way`, it can apply to any base, with 3-way merge resolving context drift.

---

## `stashed-untracked/<NNN>/...`

Present only when the corresponding row has `has_untracked=true`.

This is the verbatim contents of the third-parent commit (the untracked-files commit) extracted as a directory tree. Paths are relative to the project root.

Created via:
```bash
git archive --format=tar <sha>^3 | tar -x -C <bundle>/stashed-untracked/<NNN>/
```

To recover: copy the directory contents back into the project:
```bash
( cd <bundle>/stashed-untracked/034 && tar -cf - . ) | ( cd /path/to/project && tar -xf - )
```

---

## `README.md`

Human-readable. Required sections:

1. **Header** — project name, creation date, stash count
2. **Recovery layers description** — the 4 layers (refs, diffs, meta, untracked)
3. **Recovery recipes** — verbatim shell commands for each recovery path
4. **Format-patch footgun warning** — explicit warning that `git format-patch -1` is NOT the source of these diffs
5. **Verification command** — how to re-verify byte-equality
6. **Lifecycle guidance** — keep for ≥1 release cycle; user manages deletion

The README is generated by `build-bundle.sh` with template substitution from the actual run's values.

---

## Backup refs

Inside the project's `.git/refs/stash-backup/`:

```
.git/refs/stash-backup/000   → SHA of stash@{0} at bundle creation time
.git/refs/stash-backup/001   → ...
```

These use a minimum width of 3 zero-padded digits (matching the bundle's filename pattern). For 1000+ stashes, the number naturally extends beyond three digits (for example, `1000.diff`).

---

## Versioning

The bundle format version is implicit — `README.md` says "v1.0" in its header. Future versions may:
- Add new optional artifacts (e.g., `forensic/<NNN>.md` from Phase 4 analysis)
- Add new columns to `index.tsv` (always at the END, never in the middle)
- Add new files in known directories (always with documented purpose)

Version 1.0 will remain a strict subset of any future version. Tools written for v1.0 will work on later versions (they'll just ignore unknown artifacts).

---

## Independence guarantees

- The bundle is INDEPENDENT of the source repo. Once created, it survives:
  - `rm -rf .git` (catastrophic; bundle survives)
  - Repository corruption
  - Project relocation (paths in diffs are relative)
- The bundle is INDEPENDENT of the skill. Any tool that knows the format spec can consume it.
- The bundle DOES NOT contain the project's working tree state at any point — only the stash's recoverable content.

---

## Verification contract

A bundle is "verified" when:

1. Every `index.tsv` row has corresponding `diffs/<NNN>.diff` and `meta/<NNN>.txt` files.
2. Every `index.tsv:sha` matches `git rev-parse refs/stash-backup/<NNN>` in the source repo.
3. Every `diffs/<NNN>.diff` has `sha256sum` equal to `git stash show -p --binary <index.tsv:sha>`.
4. Every `has_untracked=true` row has a corresponding `stashed-untracked/<NNN>/` directory.

The skill's `verify-bundle.sh` script enforces 1, 2, 3, and materialized untracked-file presence/content for rows with untracked files.

## Recovery contract

A consumer of the bundle can recover any stash via either:

**Path A: cherry-pick from backup ref** (when the source repo's backup ref still exists)
```bash
cd /path/to/source/repo
git cherry-pick -m 1 refs/stash-backup/<NNN>
# If index.tsv says has_untracked=true, also copy stashed-untracked/<NNN>/.
```

**Path B: apply the bundle's diff** (works even when the source repo's backup ref is gone)
```bash
cd /path/to/source/repo
git apply --3way --check <bundle>/diffs/<NNN>.diff   # dry-run
git apply --3way        <bundle>/diffs/<NNN>.diff   # actual apply
# If index.tsv says has_untracked=true, also copy stashed-untracked/<NNN>/.
git add <changed-files>
git commit -m "recover stash@{<N>} from bundle"
```

**Path C: re-create the stash entry** (rare; when the user wants the entry back in `git stash list`)
```bash
cd /path/to/source/repo
N=<N>
NPAD=<NNN>
if grep -q '^diff --git ' <bundle>/diffs/$NPAD.diff; then
  git apply --3way --check <bundle>/diffs/$NPAD.diff
  git apply --3way        <bundle>/diffs/$NPAD.diff
fi
if awk -F'\t' -v n="$N" '$1 == n {print $11}' <bundle>/index.tsv | grep -qx true; then
  ( cd <bundle>/stashed-untracked/$NPAD && tar -cf - . ) | ( cd /path/to/source/repo && tar -xf - )
fi
git stash push --include-untracked -m "recovered: $(grep ^message= <bundle>/meta/$NPAD.txt | cut -d= -f2-)"
```

**Path D: extract untracked files only**
```bash
( cd <bundle>/stashed-untracked/<NNN> && tar -cf - . ) | ( cd /path/to/source/repo && tar -xf - )
git add <new-files>
```

---

## Tooling that can consume the bundle

- `git apply` — works directly with the diffs
- `git cherry-pick` — works with the backup refs
- This skill's `scripts/recovery-test.sh` — verifies the bundle's recovery recipes
- Any script reading `index.tsv` (TSV; trivially parsable)
- Bundle-spec-aware tools (e.g., a future "stash-archaeology" indexer)

The format is deliberately unsexy — TSV + plain text + standard diffs — so it's robust against tooling churn.
