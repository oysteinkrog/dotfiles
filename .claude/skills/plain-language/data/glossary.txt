# glossary.txt - domain/technical terms that cost NOTHING in the plain-language
# scorer. Format: one lowercase term per line, comments start with #.
# A domain term is never penalised for being rare: keep the precise word,
# simplify the sentence around it.
#
# This is the GENERAL, shipped glossary: precise vocabulary that any Initial
# Force repo would need across five domains - software engineering, .NET,
# video, imaging, and biomechanics/sports science. It is hand-built from
# domain knowledge, not mined from any one repo's docs, so it does not
# duplicate a per-project glossary generated separately for a specific
# codebase (that kind of list belongs next to the project, not in this
# shared skill).
#
# Built 2026-08-31, four source buckets:
#   1. Common software/.NET/architecture vocabulary with no exact plain
#      synonym (async, mutex, viewmodel, serialization, idempotent, etc.)
#      plus general engineering/QA process terms (unit test, feature flag,
#      canary release, distributed tracing, etc.)
#   2. Video/imaging/camera-pipeline vocabulary (codec, keyframe, demosaic,
#      bayer, rolling shutter, chromatic aberration, nyquist, etc.)
#   3. Biomechanics and sports-science vocabulary (kinematics, ground
#      reaction force, pronation, VO2 max, motor unit, etc.)
#
# Two mechanical filters were applied after drafting, so the list only
# contains words actually worth protecting:
#   - Rule 1: dropped any term that is also a key in simpler.tsv (a word
#     cannot simultaneously be "the precise term, free of charge" and "a
#     hard word with a plain synonym" - those two files must not overlap).
#   - Rule 2: dropped any single word whose Zipf frequency in
#     lexicon.tsv.gz is 4.5 or higher - a word that common is already free
#     in the cost model, so listing it here would add nothing (this is why
#     ordinary words that happen to appear in these domains, e.g. driver,
#     resolution, moment, gain, lock, are absent: they are common English
#     words first). Multi-word phrases have no single row in that table, so
#     the Zipf rule does not apply to them directly, and the scorer today
#     only ever checks one word at a time (see model.py Scorer.word_cost) -
#     a multi-word entry here is inert until a phrase-aware matcher exists,
#     kept anyway for that forward compatibility, matching simpler.tsv.
#
# Deliberately excluded as ordinary abstract English, not domain vocabulary
# (this is what makes the list conservative): words like canonical,
# estimation, validated, framing, residual, adversarial, foundational,
# taxonomy read as technical but are not precise to any of the five domains
# above - they have ordinary plain meanings and should keep costing under
# the normal lexical model, not be exempted here.
#
# Also excluded on purpose: hardware vendor/product names (Trackman,
# Bertec, Basler, GenICam, etc.), internal tool/codename vocabulary (simhw,
# autoqa, worktree, bead, nav-map, etc.), and any other term specific to one
# product's own documentation - those belong in that project's own
# generated glossary, not in this shared, general one.
