# Onboarding Artifact Template

This is the skeleton the skill creates inside the *target* project at `<project>/.claude/support-triage/`. It survives compactions and lets future sessions skip rediscovery.

```
<project>/.claude/support-triage/
├── README.md              ← orientation (this file's purpose)
├── 00-intake.md           ← complexity band, routers, owner decisions
├── 01-architecture.md     ← support code paths in the project
├── 02-channels.md         ← every place users can ask for help
├── 03-decision-matrix.md  ← project-specific issue → action map
├── 04-templates/          ← project-customized response templates
│   ├── REQUEST-INFO.md
│   ├── BILLING.md
│   ├── REFUND.md
│   └── ... (one file per category in 03-decision-matrix.md)
├── 05-policies.md         ← refund SOP, escalation paths, SLAs
├── 06-recurring-issues.md ← known issues + diagnostic shortcuts
├── 07-secrets.md          ← env var NAMES (not values)
├── 08-voice.md            ← brand voice, banned phrases, mode shifts
├── 09-knowledge-base.md   ← canonical answers + KB gaps
├── 10-metrics.md          ← FRT/MTTR/CSAT/SLA dashboard map
├── 11-runbooks/           ← project-specific high-risk runbooks
├── 12-gap-dispositions.md ← explicit manual-only/blocked/policy/evidence gaps
├── vocabularies/          ← controlled theme/persona/outcome tags for VoC loops
├── adapter-capabilities.json ← safe/unsafe action contract for adapters
├── artifacts/             ← high-risk evidence, drafts, approvals, sends, verification
├── handoffs/              ← support-handoff.json and live-escalation notes
├── outcomes/              ← Phase 6 records from live triage and fire drills
├── _detection.json        ← machine-readable surface fingerprint
├── .workspace/            ← scratch (skill_inventory.json, etc.)
└── scripts/               ← project-specific dispatchers
    ├── list-open.sh       ← emits support-adapter-v1 open-item JSON
    └── post-reply.sh      ← surface-aware send (always asks confirmation)
```

## README.md (template)

```markdown
# Support Triage — <Project Name>

This folder is the agent-readable map of how user support works for <project>.
It was generated by `/user-support-triage-for-saas-and-open-source-projects`
on <YYYY-MM-DD> and is updated whenever the support surface materially changes.

## Quick Map

| File | What it answers |
|---|---|
| `00-intake.md`       | Complexity band, routers, owner answers, source discipline |
| `01-architecture.md` | Where the code lives that handles support |
| `02-channels.md`     | Where users actually reach out |
| `03-decision-matrix.md` | How to classify and respond to each issue type |
| `04-templates/`      | Customized reply templates per category |
| `05-policies.md`     | Refunds, escalations, SLAs, voice |
| `06-recurring-issues.md` | The N most common reports + diagnosis |
| `07-secrets.md`      | Env var names + rotation policy |
| `08-voice.md`        | How the team actually writes to users |
| `09-knowledge-base.md` | Canonical answers and missing docs |
| `10-metrics.md`      | Response-time, resolution, and satisfaction metrics |
| `11-runbooks/`       | Refund, security, privacy, hostile-user, outage playbooks |
| `12-gap-dispositions.md` | Manual-only, blocked, policy, provider, and evidence gaps |
| `vocabularies/`    | Owner-approved theme/persona/outcome tags for VoC loops |
| `adapter-capabilities.json` | Which actions are safe vs owner-approved |
| `artifacts/`         | Evidence packs for high-risk sessions |
| `handoffs/`          | Machine-readable handoffs for escalations/migrations |
| `outcomes/`          | Phase 6 learning records from triage sessions |
| `_detection.json`    | Machine-readable fingerprint |

## Re-Run When

- A new support channel is added (e.g. moved from custom DB to Zendesk)
- An SLA tier or refund policy changes
- Major architecture shift (new payment provider, new auth, new email provider)
- ≥6 months since last refresh — assume drift

## Loading In A New Session

```
> Triage support for <project>.
```

The skill auto-loads this folder. No re-onboarding needed for routine triage.
```
