# Bundle Format Specification (v1.0)

The recovery bundle is a self-contained, self-describing artifact for branch + worktree rationalization. Tools other than this skill can consume it. This spec defines the format precisely so future tooling has a stable contract.

The bundle reconciles two units of management — branches and worktrees — into a single recovery story per [SKILL.md Axiom 0](../SKILL.md#the-rationalization-kernel-universal-axioms): "Worktrees are filesystem checkouts; branches are refs. They share a single recovery bundle and a single verbatim-authorization gate."

---

## Slug naming convention (load-bearing)

Throughout this spec, `<slug>` refers to a branch's filesystem-safe, collision-resistant identifier. The slug is generated by `slugify_branch` in `scripts/project-root.sh` and has the shape:

```
<safe-name>-<sha1-12>
```

Where:
- `<safe-name>` is the branch name with `/` replaced by `_` and any non-`[A-Za-z0-9._-]` characters replaced by `_`
- `<sha1-12>` is the first 12 hex chars of `sha1(branch-name)` — appended to disambiguate names that would otherwise collapse (e.g., `feature/a` and `feature_a` would both produce `feature_a` without the suffix)

Examples (the actual output of `slugify_branch`):

| branch name | slug |
|-------------|------|
| `feature/redact-secrets` | `feature_redact-secrets-ff955e2a723b` |
| `release/2.x` | `release_2.x-8d4540660462` |
| `main` | `main-b28b7af69320` |
| `agent-task-2026-04-12-attempt-3` | `agent-task-2026-04-12-attempt-3-<hash>` |

**For tooling that consumes the bundle:** the canonical source of truth for any branch's slug is the `slug` column in `index.tsv` (and the per-branch `branches.tsv`). NEVER reconstruct slugs by stripping `/` → `_` alone — you'll miss the hash suffix and look in the wrong directory. Always read `index.tsv:slug` first.

**For users following recovery recipes:** the `handoff_report.md` and the bundle's `README.md` print every slug verbatim. Copy them from the report rather than typing them by hand.

## Top-level layout

```
<project-parent>/<basename>-branch-worktree-archive-<YYYY-MM-DD>/
├── README.md                      (human-readable; recovery recipes; format-patch note)
├── object-bundle.pack             (git bundle; portable; carries all backup refs)
├── index.tsv                      (machine-readable; one row per branch + per worktree)
├── branches/
│   └── <slug>/
│       ├── meta.txt               (head SHA, merge-base, ahead/behind, …)
│       ├── commits.tsv            (one row per commit not on canonical)
│       ├── diff-vs-merge-base.diff
│       └── format-patch/
│           ├── 0001-…patch
│           ├── 0002-…patch
│           └── …
└── worktrees/
    └── <sanitized-path>/
        ├── meta.txt               (original path, branch, last commit, locks, submodules)
        ├── status.txt             (`git status --porcelain=v2` snapshot)
        ├── staged.diff            (`git diff --binary --cached`)
        ├── unstaged.diff          (`git diff --binary`)
        ├── .untracked.list        (NUL manifest; only if untracked content existed)
        └── untracked.tar.gz       (only if untracked content existed)
```

The bundle directory's name is `<basename>-branch-worktree-archive-<YYYY-MM-DD>` where:
- `<basename>` is the basename of the project root (`/data/projects/asupersync` → `asupersync`)
- `<YYYY-MM-DD>` is the UTC date of the bundle creation

The bundle lives **outside** the repo (in the parent directory) so it survives `git clean -fdx` (which the skill never runs but the user might) and doesn't pollute `git status`.

> Why two top-level subdirectories? Per [SKILL.md Axiom 0](../SKILL.md#the-rationalization-kernel-universal-axioms): branches and worktrees have different inventories and different removal mechanics. Reconciling them under a unified `index.tsv` while keeping their per-entry layouts distinct is the cleanest split.

## `index.tsv`

Tab-separated, one row per branch AND one row per worktree. Header:

```
kind  name_or_path  slug  head_sha  merge_base  ahead  behind  smell  intake_protected  verdict  bundle_paths
```

| Column | Type | Description |
|--------|------|-------------|
| `kind` | enum | `branch` or `worktree` |
| `name_or_path` | string | For branches: ref name (e.g., `feature/foo`). For worktrees: absolute path. |
| `slug` | string | Filesystem-safe bundle key. For branches, this is `slugify_branch(name_or_path)`; for worktrees, this is `sanitize_path(name_or_path)`. |
| `head_sha` | string | Full commit SHA at the branch tip OR the worktree's HEAD. |
| `merge_base` | string | `git merge-base <canonical> <head_sha>`; empty for orphan or unrelated histories. |
| `ahead` | int | `git rev-list --count <merge_base>..<head_sha>`; commits unique to this branch. |
| `behind` | int | `git rev-list --count <head_sha>..<canonical>`; commits canonical has that the branch doesn't. |
| `smell` | string | Smell category from [BRANCH-WORKTREE-SMELLS.md](BRANCH-WORKTREE-SMELLS.md) (e.g., `B1-agent-attempt`, `W1-tmp`, `B5-release-protected`, `W9-active-cwd-protected`). |
| `intake_protected` | bool | `true` if auto-protected at Phase 0 (`release/*`, `hotfix/*`, `dependabot/*`, `renovate/*`, `gh-pages`, canonical, currently-checked-out branch, active worktree). |
| `verdict` | string | Phase 5 / 6 verdict: one of the canonical 11 — `canonical` / `protected-preserve` / `already-merged` / `superseded` / `novel-and-accretive` / `partially-novel` / `novel-but-stale` / `divergent-refactor` / `dirty-worktree-only` / `garbage` / `unknown` — plus the sub-case `superseded-by-newer-branch`. (Some smells in [BRANCH-WORKTREE-SMELLS.md](BRANCH-WORKTREE-SMELLS.md) carry annotation tags such as `user-owned-sandbox` that map to `protected-preserve` in the verdict column with the smell preserved in the `smell` column.) |
| `bundle_paths` | csv | Comma-separated list of bundle artifacts for this entry. Include the entry directory plus key files (e.g., `branches/feature_foo-<hash>/,branches/feature_foo-<hash>/meta.txt,branches/feature_foo-<hash>/diff-vs-merge-base.diff,branches/feature_foo-<hash>/format-patch/`). |

Example branch row:

```
branch	feature/parse-hardening	feature_parse-hardening-ff955e2a723b	7f3a1b8...	2c8e9d0...	2	14	B10-feature	false	novel-and-accretive	branches/feature_parse-hardening-ff955e2a723b/,branches/feature_parse-hardening-ff955e2a723b/meta.txt,branches/feature_parse-hardening-ff955e2a723b/commits.tsv,branches/feature_parse-hardening-ff955e2a723b/diff-vs-merge-base.diff,branches/feature_parse-hardening-ff955e2a723b/format-patch/
```

Example worktree row:

```
worktree	/data/projects/asupersync-wt-tokio-rich	data__projects__asupersync-wt-tokio-rich-8a3d2c9e1f00	8a3d2c9...	-	-	-	W2-sibling-wt	false	dirty-worktree-only	worktrees/data__projects__asupersync-wt-tokio-rich-8a3d2c9e1f00/,worktrees/data__projects__asupersync-wt-tokio-rich-8a3d2c9e1f00/meta.txt,worktrees/data__projects__asupersync-wt-tokio-rich-8a3d2c9e1f00/status.txt,worktrees/data__projects__asupersync-wt-tokio-rich-8a3d2c9e1f00/staged.diff,worktrees/data__projects__asupersync-wt-tokio-rich-8a3d2c9e1f00/unstaged.diff,worktrees/data__projects__asupersync-wt-tokio-rich-8a3d2c9e1f00/.untracked.list,worktrees/data__projects__asupersync-wt-tokio-rich-8a3d2c9e1f00/.untracked.sha256,worktrees/data__projects__asupersync-wt-tokio-rich-8a3d2c9e1f00/untracked.tar.gz
```

## Per-branch layout: `branches/<slug>/`

`<slug>` is generated by `slugify_branch` in `scripts/project-root.sh`: replace unsafe characters (including `/`) with `_`, cap the visible prefix, and append a 12-character hash suffix. Treat the `slug` column in `index.tsv` as canonical.

### `meta.txt`

Plain text, one key=value per line. Keys (all required unless noted):

```
name=<branch-name>
slug=<slug>
head_sha=<full sha>
merge_base=<full merge-base sha; empty for unrelated histories>
canonical=<canonical branch name>
ahead=<int>
behind=<int>
commits_ahead=<int>
cherry_plus=<int>
cherry_minus=<int>
upstream=<remote/branch | none>
upstream_status=<ok | gone | none>
last_date=<ISO 8601 committer date of head_sha>
author=<head commit author>
subject=<head commit subject>
age_days=<int>
worktree_path=<absolute path if checked out, else empty>
touched_files=<int>
insertions=<int>
deletions=<int>
files_changed=<int>
prefix_family=<branch-name prefix family>
```

Protection state lives in the top-level `index.tsv` row (`intake_protected` plus
the `smell` verdict context). Branch `meta.txt` keeps only branch-local facts
captured from inventory.

### `commits.tsv`

Tab-separated, one row per commit on the branch but not on canonical (i.e., the `ahead` set). Header:

```
sha  parent_sha  date_utc  author  subject  files_changed  insertions  deletions
```

Example:

```
def987a	abc123f	2026-04-29T14:22:11Z	cinthi	feat: add OK-packet length cap	2	18	0
1a2b3c4	def987a	2026-04-30T09:11:42Z	cinthi	test: add OK-packet overflow regression	1	28	0
```

The list is in reverse-chronological order (newest first) to match `git log` defaults.

### `diff-vs-merge-base.diff`

The verbatim output captured at bundle-build time:

```bash
git diff --binary <merge-base>...<head_sha> > diff-vs-merge-base.diff
```

Note the **three-dot** syntax (`<merge-base>...<head_sha>`) — this gives the symmetric difference relative to the merge base, which is the right semantic for "what does this branch add on top of canonical."

The diff format:
- Standard unified diff
- Includes `diff --git a/PATH b/PATH` headers
- Includes `index <old>..<new>` lines
- Includes `--- a/PATH` and `+++ b/PATH` markers for normal text patches
- Includes `GIT binary patch` payloads for tracked binary files
- For new files: `new file mode <mode>`; for deleted: `deleted file mode <mode>`

The diff applies cleanly via `git apply` to a working tree at the merge-base commit. With `git apply --3way`, it can apply to canonical's current tip with 3-way merge resolving context drift.

### `format-patch/*.patch`

The verbatim output captured at bundle-build time:

```bash
git format-patch <merge-base>..<head_sha> --output-directory format-patch/
```

This produces one `0001-<subject>.patch` per commit in the `ahead` set, in topological order. Each patch is a self-contained `git am`-applyable file with author, date, subject, message, and the full diff.

**Format-patch IS valid for branches.** Per [SKILL.md Axiom 7](../SKILL.md#the-rationalization-kernel-universal-axioms): "git format-patch IS valid for branches; it is NOT for stashes. A branch is a normal commit chain — git format-patch <merge-base>..<branch> produces a clean ordered series. If you came from git-stash-janitor, do not generalize the 'format-patch is wrong' rule."

> Cross-link: this is the explicit *reverse* of the sibling skill's [BUNDLE-FORMAT-SPEC.md](../../git-stash-janitor/references/BUNDLE-FORMAT-SPEC.md) and [FAILURE-MODES.md](../../git-stash-janitor/references/FAILURE-MODES.md), which warn that `git format-patch -1 stash@{N}` is wrong because a stash is a merge commit, not a normal chain. Branches are normal chains; format-patch is correct.

## Per-worktree layout: `worktrees/<sanitized-path>/`

`<sanitized-path>` is produced by `sanitize_path` in `scripts/project-root.sh`: strip the leading `/`, replace path separators with `__`, replace unsafe characters with `_`, cap the visible prefix, and append a 12-character content hash (e.g., `/data/projects/asupersync-wt-foo` → `data__projects__asupersync-wt-foo-<hash>`). Treat the `slug` column in `index.tsv` as canonical.

### `meta.txt`

Plain text, one key=value per line:

```
path=<absolute path>
branch=<branch-name | DETACHED:<sha> | (no branch)>
detached=<true | false>
bare=<true | false>
locked=<true | false>
prunable=<true | false>
last_sha=<full sha at capture time>
last_date=<ISO 8601>
dirty=<true | false>
staged_diff_lines=<int>
unstaged_diff_lines=<int>
untracked_total_bytes=<int>
untracked_file_count=<int>
age_days=<int>
inside_main_repo=<true | false>
active_worktree=<true | false>
submodules_initialized=<yes | no | partial(M/N) | none>
```

### `status.txt`

Verbatim `git status --porcelain=v2` output captured at bundle-build time:

```bash
git -C <worktree-path> status --porcelain=v2 > status.txt
```

Per [WORKTREE-STATE.md](WORKTREE-STATE.md), this is the snapshot used to verify dirty-state hasn't shifted between Phase 3 and Phase 10. Use `--porcelain=v2` (not v1) for machine readability.

### `staged.diff`

```bash
git -C <worktree-path> diff --binary --cached > staged.diff
```

The staged-but-not-committed content. Empty when there were no staged changes.

### `unstaged.diff`

```bash
git -C <worktree-path> diff --binary > unstaged.diff
```

The unstaged working-tree changes vs. the index. Empty when there were no unstaged changes.

### `untracked.tar.gz`

Only present when `untracked_file_count` in `meta.txt` is greater than zero. The adjacent `.untracked.list` is a
NUL-delimited manifest and is part of the recovery contract. Contains
untracked-but-not-ignored files only:

```bash
git -C <worktree-path> ls-files --others --exclude-standard -z > .untracked.list
tar --null -czf untracked.tar.gz \
    -C <worktree-path> \
    -T .untracked.list
```

Paths inside the tarball are relative to the worktree root, so recovery is:

```bash
tar --null -xzf <bundle>/worktrees/<slug>/untracked.tar.gz \
  -C <recovery-target> \
  -T <bundle>/worktrees/<slug>/.untracked.list
```

## The `object-bundle.pack`

The single most important artifact for long-term recovery — a portable git bundle over the entire `refs/branch-rationalization-backup/*` namespace.

```bash
git bundle create <bundle-dir>/object-bundle.pack \
  refs/branch-rationalization-backup/*
```

Properties:

- **Self-contained.** The bundle includes all reachable commit objects, trees, and blobs. It can be cloned-from or fetched-from in any other repo.
- **Portable.** Move it to another machine via `tar`, `rsync`, or any file transfer. It survives the source repo's deletion.
- **Outlives ref namespace collapse.** Even if `refs/branch-rationalization-backup/*` is later cleaned up (intentionally or accidentally), the bundle still has every object.
- **Verifiable.** `git bundle list-heads <bundle>/object-bundle.pack` enumerates the refs the bundle carries; `git bundle verify` confirms object integrity.

Recovery from the bundle (works even on a fresh clone):

```bash
# Fetch all backup refs from the bundle into a fresh repo:
git fetch <bundle-dir>/object-bundle.pack refs/branch-rationalization-backup/*:refs/branch-rationalization-recovered/*

# Or list what's inside without fetching:
git bundle list-heads <bundle-dir>/object-bundle.pack
```

> Why this matters: per [SKILL.md "The One Rule"](../SKILL.md): "Backup refs in refs/branch-rationalization-backup/* plus a git bundle over the whole namespace plus per-worktree dirty-state captures are the gold standard."

## Backup refs

Inside the project's `.git/refs/branch-rationalization-backup/`:

```
.git/refs/branch-rationalization-backup/<slug>   → SHA at bundle creation time
```

Where `<slug>` is the hash-suffixed `slug` column from `index.tsv` (matching the `branches/<slug>/` directory).

These are byte-identical copies of the live ref AT Phase 3 verification time. Per [SKILL.md Axiom 4](../SKILL.md#the-rationalization-kernel-universal-axioms) (beneficiary-style coherence):

```
refs/heads/<branch> @ Phase 3 verify time
   ==
refs/branch-rationalization-backup/<slug>
   ==
git bundle list-heads object-bundle.pack | grep <slug>
   ==
sha256 of (branches/<slug>/diff-vs-merge-base.diff applied to branches/<slug>/meta.txt:merge_base)
```

If any of these disagree at Phase 3 verify time, the bundle is unsafe and the run halts. See "Verification protocol" below.

## `README.md`

Human-readable. Required sections:

1. **Header** — project name, creation date, branch count, worktree count, total disk reclaimable
2. **Recovery layers description** — the 5 layers (backup refs, object bundle, per-branch diffs/format-patch, per-worktree dirty captures, meta + index)
3. **Recovery recipes** — verbatim shell commands for each recovery path (cross-link to [RECOVERY-RECIPES.md](RECOVERY-RECIPES.md))
4. **Format-patch note** — explicit note that format-patch IS valid for branches in this bundle (the inverse of git-stash-janitor's footgun warning)
5. **Verification command** — how to re-verify byte-equality and bundle-list-heads round-trip
6. **Lifecycle guidance** — keep for ≥1 release cycle (typically 1–4 weeks); user manages deletion (DCG blocks `rm -rf`); the skill never deletes

The README is generated by `scripts/build-bundle.sh` with template substitution from the actual run's values.

## Verification protocol

A bundle is "verified" when ALL of the following pass:

### 1. Per-entry artifact presence

Every `index.tsv` row's `bundle_paths` list resolves to existing artifacts in the bundle.

### 2. Backup ref byte-equality

For every branch row in `index.tsv`:

```bash
live=$(git rev-parse refs/heads/<branch-name>)
back=$(git rev-parse refs/branch-rationalization-backup/<slug>)
[[ "$live" == "$back" ]] || halt "MISMATCH for $slug"
```

### 3. `git bundle list-heads` round-trip

```bash
git bundle list-heads <bundle>/object-bundle.pack | sort > bundle_refs.txt
awk -F'\t' '$1 == "branch" { print $4 " refs/branch-rationalization-backup/" $3 }' \
  index.tsv | sort > expected_refs.txt
diff bundle_refs.txt expected_refs.txt   # must be empty
```

### 4. Per-branch diff sha256 round-trip

For every branch row in `index.tsv`:

```bash
expected=$(git diff --binary <merge-base> <head_sha> | sha256sum | awk '{print $1}')
actual=$(sha256sum <bundle>/branches/<slug>/diff-vs-merge-base.diff | awk '{print $1}')
[[ "$expected" == "$actual" ]] || halt "DIFF MISMATCH for $slug"
```

### 5. Per-branch format-patch series count match

For every branch row:

```bash
patch_count=$(ls <bundle>/branches/<slug>/format-patch/*.patch 2>/dev/null | wc -l)
ahead_count=$(awk -F'\t' -v slug="$slug" '$1 == "branch" && $3 == slug { print $6 }' index.tsv)
[[ "$patch_count" == "$ahead_count" ]] || halt "PATCH COUNT MISMATCH for $slug"
```

### 6. Per-worktree dirty re-snapshot

For every worktree row in `index.tsv` where the worktree was non-clean:

```bash
# Compare bundle's status.txt to a fresh re-snapshot:
fresh=$(mktemp)
git -C <worktree-path> status --porcelain=v2 > "$fresh"
diff <bundle>/worktrees/<slug>/status.txt "$fresh" \
  || warn "Worktree $slug has drifted since Phase 3 — re-capture before Phase 10"
```

If steps 1–5 fail, the run halts. Step 6 is a soft warning — drift is expected for active worktrees and triggers a re-capture, not a halt.

The skill's `scripts/verify-bundle.sh` enforces all six steps.

## Recovery API — One-Liners

The full recovery recipe catalogue is in [RECOVERY-RECIPES.md](RECOVERY-RECIPES.md). The bundle's `README.md` lists the most-common one-liners:

**Recover a deleted branch (preferred — uses backup ref):**

```bash
git branch <branch-name> refs/branch-rationalization-backup/<slug>
```

**Recover a deleted branch when backup ref is gone (use the bundle):**

```bash
git fetch <bundle>/object-bundle.pack \
  refs/branch-rationalization-backup/<slug>:refs/heads/<branch-name>
```

**Recover via diff replay (when even the bundle's history is inapplicable):**

```bash
git checkout <merge-base>
git apply --3way <bundle>/branches/<slug>/diff-vs-merge-base.diff
git add . && git commit -m "recover <branch-name> from bundle diff replay"
```

**Recover via format-patch series (preserves per-commit history):**

```bash
git checkout -b <branch-name> <merge-base>
git am <bundle>/branches/<slug>/format-patch/*.patch
```

**Recover a removed worktree's dirty state into a fresh worktree:**

```bash
git worktree add <new-path> <branch-name>
git -C <new-path> apply --3way <bundle>/worktrees/<slug>/staged.diff
git -C <new-path> apply --3way <bundle>/worktrees/<slug>/unstaged.diff
tar --null -xzf <bundle>/worktrees/<slug>/untracked.tar.gz \
  -C <new-path> \
  -T <bundle>/worktrees/<slug>/.untracked.list
```

**List everything in the bundle:**

```bash
column -t -s $'\t' <bundle>/index.tsv | less
git bundle list-heads <bundle>/object-bundle.pack
```

## Versioning

The bundle format version is implicit — `README.md` says "v1.0" in its header. Future versions may:

- Add new optional artifacts (e.g., `forensic/<slug>.md` from Phase 5 deeper analysis)
- Add new columns to `index.tsv` (always at the END, never in the middle)
- Add new files in known directories (always with documented purpose)
- Add a `harmonization/<file-slug>/variant-matrix.md` for files harmonized in Phase 7

Version 1.0 will remain a strict subset of any future version. Tools written for v1.0 will work on later versions (they ignore unknown artifacts).

---

## Independence guarantees

- The bundle is INDEPENDENT of the source repo. Once created, it survives:
  - `rm -rf .git` (catastrophic; the bundle's `object-bundle.pack` survives and can re-seed any clone)
  - Repository corruption
  - Project relocation (paths in diffs are relative; worktree paths in `meta.txt` are recorded but the diffs apply to any matching tree)
- The bundle is INDEPENDENT of the skill. Any tool that knows the format spec can consume it.
- The bundle DOES NOT contain the project's working tree state at any point — only the recoverable content of branches and the dirty state of worktrees.

---

## Tooling that can consume the bundle

- `git apply` — works directly with the per-branch diffs and per-worktree staged/unstaged diffs
- `git am` — works with the per-branch format-patch series
- `git fetch` — pulls from `object-bundle.pack` directly
- `git bundle list-heads` / `git bundle verify` — bundle introspection and integrity check
- `git cherry-pick` — works with the backup refs (after they're fetched from the bundle)
- This skill's `scripts/verify-bundle.sh` — runs all six verification steps
- Any script reading `index.tsv` (TSV; trivially parsable)
- Bundle-spec-aware tools (e.g., a future "branch-archaeology" indexer)

The format is deliberately unsexy — TSV + plain text + standard diffs + a single `.pack` file — so it's robust against tooling churn.
