# Worked Proof: Ville's Inequality + the E-Process Supermartingale Property

Why anytime-valid testing works: the rigorous reason a CI gate can check after every observation and still maintain `P(false reject) ≤ α`, without Bonferroni correction. This file is the proof companion to `e-process-worked.md` (numerical worked example) and to [`pattern:70-E-PROCESSES`](../patterns/70-E-PROCESSES.md) (operational pattern). Cited in [`methodology/KERNEL.md § K-6 Anytime-Valid Testing`](../methodology/KERNEL.md).

---

## 1. The setup

Let `H_0` be the null hypothesis. In the gauntlet's invariant monitoring (e.g., "softmax sums to 1.0 ± 1e-7"), `H_0` is the assertion that the invariant holds in expectation.

Let `(Y_t)_{t ≥ 1}` be the observation stream — `Y_t = 1` if the invariant holds at observation `t`, `Y_t = 0` if it violates. Under `H_0`, we assume each `Y_t` has some probability `1 - p_0` of being `0` (a violation), where `p_0` is small (e.g., `1e-9` for hardware-enforced calibration, `1e-6` for software-enforced).

An **e-process** `(E_t)_{t ≥ 0}` is a non-negative process with `E_0 = 1` such that

```
E_{H_0}[E_t | F_{t-1}] ≤ E_{t-1}
```

where `F_{t-1}` is the σ-algebra generated by `Y_1, ..., Y_{t-1}`. This is the **supermartingale** property under `H_0`.

The gauntlet's e-process construction (per [`pattern:70-E-PROCESSES`](../patterns/70-E-PROCESSES.md)):

```
E_t = E_{t-1} · ((1 - λ) + λ · Y_t / p_0)
```

with `0 < λ < 1` (decay-vs-multiply weight) and `p_0` the null-violation probability.

## 2. Why this is a supermartingale under H_0

Take the conditional expectation under `H_0`:

```
E_{H_0}[E_t | F_{t-1}] = E_{t-1} · E_{H_0}[(1 - λ) + λ · Y_t / p_0 | F_{t-1}]
                      = E_{t-1} · ((1 - λ) + λ / p_0 · E_{H_0}[Y_t | F_{t-1}])
```

Under `H_0`, `P(Y_t = 1) = 1 - p_0` and `P(Y_t = 0) = p_0`, so `E_{H_0}[Y_t | F_{t-1}] = 1 - p_0`. Substituting:

```
E_{H_0}[E_t | F_{t-1}] = E_{t-1} · ((1 - λ) + λ · (1 - p_0) / p_0)
```

For this to satisfy the supermartingale property, we need

```
(1 - λ) + λ · (1 - p_0) / p_0 ≤ 1
```

Rearranging:

```
λ · (1 - p_0) / p_0 ≤ λ
                ⟺ (1 - p_0) / p_0 ≤ 1
                ⟺ 1 - p_0 ≤ p_0
                ⟺ p_0 ≥ 1/2
```

Wait — that's false for `p_0 = 1e-9`! Let me re-derive more carefully.

### Corrected derivation

The supermartingale property `E_{H_0}[E_t | F_{t-1}] ≤ E_{t-1}` requires

```
E_{H_0}[(1 - λ) + λ · Y_t / p_0] ≤ 1
   ⟺ (1 - λ) + λ · E_{H_0}[Y_t / p_0] ≤ 1
   ⟺ (1 - λ) + λ · E_{H_0}[Y_t] / p_0 ≤ 1
```

But `E_{H_0}[Y_t]` is the expected value of `Y_t` under H_0. The gauntlet's `Y_t = 1` indicates the invariant **violates** (which is what we want the e-process to be sensitive to). So under H_0 where violations are rare, `E_{H_0}[Y_t] = p_0` (probability of violation).

Substituting `E_{H_0}[Y_t] = p_0`:

```
(1 - λ) + λ · p_0 / p_0 = (1 - λ) + λ = 1
```

So `E_{H_0}[E_t | F_{t-1}] = E_{t-1} · 1 = E_{t-1}` — supermartingale (in fact a martingale) under H_0. ✓

The earlier confusion was a sign convention: in the e-process construction, `Y_t = 1` ↔ violation (the e-value grows on violations because each violation is `1 / p_0`-fold evidence against H_0). The numerical worked example in `e-process-worked.md` follows this convention.

## 3. Ville's inequality (Ville 1939)

Let `(E_t)` be a non-negative supermartingale with `E_0 = 1`. Then for any `c > 0`:

```
P(sup_{t ≥ 0} E_t ≥ c) ≤ 1/c
```

**Proof sketch (Doob 1953 § VII.3.2).** For each `n`, define the stopping time `τ_n = inf{t : E_t ≥ c} ∧ n`. By Doob's optional stopping theorem for non-negative supermartingales:

```
E[E_{τ_n}] ≤ E_0 = 1
```

Decompose:

```
E[E_{τ_n}] = E[E_{τ_n} · 1_{τ_n < n}] + E[E_n · 1_{τ_n = n}]
          ≥ E[E_{τ_n} · 1_{τ_n < n}]
          ≥ c · P(τ_n < n)
```

(the last step uses `E_{τ_n} ≥ c` on the event `τ_n < n` because that's exactly when the supremum was achieved). So `c · P(τ_n < n) ≤ 1`, giving `P(τ_n < n) ≤ 1/c`. Taking `n → ∞` and using continuity from below:

```
P(sup_{t ≥ 0} E_t ≥ c) = P(∃ t : E_t ≥ c) ≤ 1/c
```

QED. □

## 4. Setting the threshold

For Type-I error budget `α`, set the rejection threshold `c = 1/α`. Then:

```
P_{H_0}(∃ t : E_t ≥ 1/α) ≤ α
```

This is the **anytime-valid** guarantee — no matter how many times we look at `E_t` and decide whether to reject, the false-rejection rate is at most `α`. **No Bonferroni correction.**

For software-enforced calibration: `α = 0.001` → reject when `E_t ≥ 1000`.

For hardware-enforced calibration: `α = 1e-6` → reject when `E_t ≥ 1e6`.

## 5. Why arithmetic-mean aggregation across invariants is conservative

The gauntlet monitors 5-10 invariants in parallel (per [`pattern:70-E-PROCESSES § Per-invariant calibration`](../patterns/70-E-PROCESSES.md)). The global e-value is the arithmetic mean:

```
E_global,t = (1/K) · Σ_{k=1}^{K} E_t^{(k)}
```

**Claim:** if each `(E_t^{(k)})` is a supermartingale under `H_0` (the per-invariant null), then `(E_global,t)` is also a supermartingale under the global null (all invariants hold), **regardless of dependence between the per-invariant streams**.

**Proof:** linearity of conditional expectation.

```
E_{H_0}[E_global,t | F_{t-1}] = (1/K) · Σ_k E_{H_0}[E_t^{(k)} | F_{t-1}]
                              ≤ (1/K) · Σ_k E_{t-1}^{(k)}
                              = E_global,t-1
```

The supermartingale property survives arithmetic mean. □

Why NOT geometric mean (product): the product of supermartingales is NOT generally a supermartingale unless the streams are independent. For ML-class invariants where INV-3 (loss monotonicity) and INV-4 (gradient norm bounded) are highly dependent, the product can grow much faster under the joint null than either factor alone — producing **false** rejections. Arithmetic mean is robust to dependence; product is not.

Per the gauntlet's [Q-051] from the FrankenSQLite bibles: *"under arbitrary dependence between invariants, only arithmetic-mean aggregation preserves the anytime-valid guarantee; we pay for it in conservatism but gain robustness to dependence we don't know about."*

## 6. The `λ` decay parameter

Why `λ < 1` (not `λ = 1`):

If `λ = 1`, the construction becomes `E_t = E_{t-1} · Y_t / p_0`. A single isolated violation `(Y_t = 1)` jumps the e-value by `1 / p_0` (e.g., `1e9` for hardware-enforced). Then if no further violations occur for thousands of observations, `E_t` stays at this elevated level — making the test prone to **false rejection on a single fluke**.

With `λ < 1`, the construction is `E_t = E_{t-1} · ((1 - λ) + λ · Y_t / p_0)`. A single isolated violation pushes E up by `(1 - λ) + λ / p_0`, but each subsequent non-violation observation contracts by factor `(1 - λ) + λ · 0 / p_0 = (1 - λ)`. So E decays geometrically with rate `1 - λ` toward 0, making the test sensitive to **bursts** of violations (which signal real regressions) and robust to isolated flukes (which signal stable rare events).

Choose `λ` such that the time-to-baseline after one isolated violation is reasonable:

```
λ^k · (1/p_0) ≈ 1   ⟺  k = -ln(p_0) / ln(1/λ)
```

For software-enforced (`p_0 = 1e-6, λ = 0.9`): `k = -ln(1e-6) / ln(1/0.9) ≈ 13.8 / 0.105 ≈ 131 obs`. One isolated FAIL takes ~131 PASS observations to wash out. Tight enough to surface real regressions; loose enough that flukes self-resolve.

For hardware-enforced (`p_0 = 1e-9, λ = 0.999`): `k = -ln(1e-9) / ln(1/0.999) ≈ 20.7 / 0.001 ≈ 20,700 obs`. Hardware violations basically never wash out — appropriate because they're never flakes.

## 7. Connection to the conformal-band ratchet

E-processes answer "is this invariant violating *right now*?" (decisive: reject when `E_t ≥ 1/α`).

The conformal band ([`pattern:75-BAYESIAN-CONFORMAL-SCORE`](../patterns/75-BAYESIAN-CONFORMAL-SCORE.md)) answers "what's our cumulative parity confidence over a window?" (continuous: lower-bound used as ratchet input).

They're orthogonal but complementary:
- E-process: per-invariant, per-observation, decisive rejection. Used to **stop bad releases** mid-flight.
- Conformal band: per-pillar, per-window, cumulative lower-bound. Used to **gate release decisions** at certification time.

Per [Q-052]: *"the e-process is the smoke alarm; the conformal lower-bound is the building inspector."*

## 8. Implementation gotchas

- **Floating-point underflow:** for hardware-enforced calibration, `(1/p_0)^N` for large `N` can overflow `f64::MAX` (~1.8e308). Use **log-space** internally: track `log E_t` and threshold against `log(1/α)`. Convert to E only for display.
- **Reset across rounds:** the gauntlet resets `E_t = 1` at the start of each Phase 11 round (per [`replay_harness.rs`](../patterns/85-ADVERSARIAL-SEARCH.md)). This is intentional — round boundaries are change-points; the prior round's evidence should not carry over.
- **Calibration drift:** if `p_0` is misestimated (e.g., set to `1e-9` when actual null violation rate is `1e-6`), the test becomes either overly conservative (Type-II inflation) or anti-conservative (Type-I inflation). Periodically re-estimate `p_0` from null-period observations.
