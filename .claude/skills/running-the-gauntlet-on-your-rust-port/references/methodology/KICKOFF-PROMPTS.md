# KICKOFF-PROMPTS — Per-Mode Verbatim Kickoff Prompts

Use these as the very first message the orchestrator emits when starting a gauntlet run in a given mode. Each prompt is paste-ready; placeholders are written as `<PLACEHOLDER>` and substituted by the orchestrator from values gathered at the Up-Front Confirmations step (see [SKILL.md § Up-Front Confirmations](../../SKILL.md)).

Two intake flavors per mode:
- **Fresh start** — `<workspace>/` does not yet exist; toolchain may or may not be installed; Phase 0 will run from scratch.
- **Resuming** — `<workspace>/` already exists with at least one round of artifacts; the orchestrator picks up from where the previous agent left off (compaction-survival contract — see [PHASES.md § Compaction-survival contract](../PHASES.md)).

The orchestrator chooses the mode via [MODE-ROUTER.md § Auto-detect heuristic table](MODE-ROUTER.md) and confirms with the user before dispatching the prompt.

```

Goal: certify <PORT_BASENAME> for release against the pinned reference <REFERENCE_NAME>-<REFERENCE_VERSION>. Produce the full release-readiness bundle.

Project class: <PROJECT_CLASS> (SQL / RESP / Numerical-Python / ML-System / HTTP-Protocol).

Required artifacts (per references/PHASES.md exit criteria):
- All phase0_*.{md,json} outputs (toolchain inventory, project-class detection, oracle preflight green)
- phase1_recon_<crate>.md per crate + phase1_unified_recon.md

- Three-tier equivalence labeled per artifact (Tier 1 byte / Tier 2 canonical / Tier 3 logical).
- FailureBundle with first_divergence_jsonptr populated per divergence.

Stop condition:
- scripts/convergence-tracker.sh exits 0

- Top of FINAL_GAUNTLET_REPORT.md says CERTIFIED
```

### Resuming a prior run

```
You are RESUMING the running-the-gauntlet-on-your-rust-port skill in `gauntlet-full` mode against <TARGET_PATH>.

Workspace exists at <WORKSPACE_PATH>. Inspect its current state before doing anything.

Bootstrap reentry:
1. If present, read <WORKSPACE_PATH>/reports/convergence_tracker.json — note round_count, clean_last_two, last_two_findings, open_hypothesis_count.
2. Read the most recent <WORKSPACE_PATH>/round_<N>/synthesis.md — understand where we left off.
3. List durable workspace status: scripts/gauntlet-status.sh <WORKSPACE_PATH> --json
4. Identify the LAST PHASE that completed cleanly. Resume from the NEXT phase.

Resumption discipline:
- Do NOT redo completed phases unless their inputs have changed (e.g., reference version bumped → Phase 2 redo → cascade).
- Do NOT silently overwrite another agent's in-progress work; check for Agent Mail reservations on `gauntlet-<run-id>-*` thread IDs.
- If a phase is mid-execution (e.g., Phase 11 round_<N>/ exists but synthesis.md does not), continue that round, then proceed to the next.
- If `reports/convergence_tracker.json` is stale (>24h), recompute via `scripts/convergence-tracker.sh <WORKSPACE_PATH>` before claiming any `clean_last_two` / open-hypothesis count.

Goal: continue toward the same stop condition as the fresh-start prompt. If the workspace state is inconsistent (e.g., `round_<N>/` exists beyond `reports/convergence_tracker.json.round_count` after rerunning the tracker), STOP and surface to the user before fabricating progress.

Everything else: same as the fresh-start prompt. Read the kernel, the phases, the operators. Cite K-N axioms in artifacts.
```

## `harden-pillar` kickoff

```
You are running the running-the-gauntlet-on-your-rust-port skill in `harden-pillar` mode against <TARGET_PATH>.

The pillar regressing: <PILLAR> (perf | conformance | surface).

Trigger evidence: <ONE_LINE_DESCRIPTION_OF_THE_REGRESSION_OR_QUARANTINE>
(e.g., "ratchet quarantine triggered on conformance pillar — round_18/conformance/failures/ shows 7 new TrueDivergence FailureBundles in the metamorphic-Predicate lane")

Goal: focus ALL parallel capacity on the <PILLAR> pillar; restore the ratchet to green; do NOT expand to the other pillars.

Workspace: <WORKSPACE_PATH> (already exists; this is a resumption-like flow)
Tier: <TIER>

Phase loop (pillar-scoped):
- Phase 0: workspace re-init (oracle preflight must be green; if red, the regression is environmental, halt)
- Phase 1: SCOPED recon — only the <PILLAR>'s surface region (e.g., for perf-pillar: only crates with hot-path counters; for conformance-pillar: only crates with oracle entry points; for surface-pillar: only the FeatureUniverse + InvariantCatalog modules)
- Phase 5 OR 6 OR 7: harness expansion for the <PILLAR> pillar ONLY
- Phase 9: SCOPED baseline against the <PILLAR>'s lanes
- Phase 10: idea-wizard scoped to <PILLAR>
- Phase 11: SCOPED iteration (≥5 rounds, ≥2 clean — relaxed from full ≥10 because the search space is one pillar)
- Phase 12: pillar-architect drafts isomorphic rewrites for every CONFIRMED_GAP
- Phase 13: pillar-scoped bead graph
- Phase 14: pillar-scoped fresh-eyes (3 reviewers; ≥1 clean round; the bar is "are the fixes correct?", not "is the whole port re-reviewed?")
- Phase 15: OPTIONAL — soak only on the <PILLAR>'s lanes (e.g., for conformance: differential fuzz; for perf: BOCPD on the pillar's score stream)
- Phase 16: <WORKSPACE_PATH>/PILLAR_REMEDIATION_REPORT.md — what regressed, the bead trail, the new ratchet state, retry-condition predicates for any deferred sub-gaps.

FORBIDDEN in this mode:
- Touching the other two pillars' harnesses (out of scope; defer to next gauntlet-full).
- Promoting a fix that lowers a per-category bound on a non-regressed pillar (the conformal-ratchet is strictly monotone — see K-6).

- Phase 14 ≥1 clean round

- Updated <PILLAR>-side ledger entries with retry-condition predicates for any deferred sub-gaps

Discipline: same axioms. Special focus: K-3 (negative evidence first-class — every rejected remediation alternative lands in the ledger) and K-4 (both gates same window — if perf-pillar, your fix must not break the conformance baseline in the same run).

Read these references first:
- references/methodology/KERNEL.md
- references/methodology/KEEP-GATE-RULES.md (if perf-pillar)
- references/methodology/CONFORMAL-RATCHET.md (if conformance-pillar)
```

## `incremental-rebase` kickoff

```
You are running the running-the-gauntlet-on-your-rust-port skill in `incremental-rebase` mode against <TARGET_PATH>.

The port's main branch moved since the last green gauntlet run. Goal: re-run ONLY the affected phases.

Workspace: <WORKSPACE_PATH> (already exists; last green run tagged at <WORKSPACE_PATH>/last_green_sha)
Tier: <TIER>

Phase loop (delta):
1. Phase 0 (workspace reuse — re-run oracle preflight; halt on red)
2. Derive affected phases from `git diff <last-green-sha>..HEAD --name-only` + `crates/*/PHASE_OWNERS.toml` → affected_phases.json (or run a project-local `scripts/detect-affected-phases.sh` if present)
3. Phase 1 DELTA: only re-recon crates whose files appear in `git diff <last-green-sha>..HEAD --name-only`
4. Phase 9 DELTA: only re-baseline workload families flagged by the affected-phase analysis (or by a project-local `scripts/detect-affected-benches.sh` if present)
5. If any baseline diverges from the persisted ratchet by more than the configured thresholds:
   - Phases 11-14 SCOPED to the affected lanes (≥3 rounds, ≥1 clean)
6. Phase 16: re-stamp <WORKSPACE_PATH>/RELEASE_CERTIFICATION.md with the new git SHA + delta summary

Required artifacts:
- <WORKSPACE_PATH>/incremental_<NEW_GIT_SHA>/git_diff_summary.md
- <WORKSPACE_PATH>/incremental_<NEW_GIT_SHA>/affected_phases.json + affected_lanes.json
- <WORKSPACE_PATH>/incremental_<NEW_GIT_SHA>/per-lane re-baseline outputs
- <WORKSPACE_PATH>/incremental_<NEW_GIT_SHA>/REBASE_REPORT.md (what changed vs. last green; per-lane verdict; new ratchet state)

FORBIDDEN in this mode:
- Re-iterating unaffected lanes (wastes compute and risks introducing drift).
- Skipping the git diff analysis (would silently miss affected lanes).
- Promoting a fix on an affected lane that touches an UNaffected lane (out of scope).

Stop condition:
- All affected lanes re-baseline within ratchet thresholds
- Any divergence resolved via scoped remediation
- scripts/final-report-builder.sh <WORKSPACE_PATH> --incremental exits 0
- REBASE_REPORT.md committed
- New last_green_sha updated

Discipline: same axioms. K-11 is critical here — artifact_id MUST stay stable across runs that test the same thing (the rebase changes run_id, NOT artifact_id).

Read these references first:
- references/methodology/KERNEL.md (especially K-4, K-11)
- references/methodology/CONFORMAL-RATCHET.md
- references/PHASES.md
```

## Common confusions

- **The kickoff prompts are verbatim by design.** The orchestrator does NOT paraphrase. The discipline references (KERNEL.md, KEEP-GATE-RULES.md, etc.) are quoted by section number for traceability.
- **Don't merge "fresh start" with "resuming" intakes.** The differences (workspace existence, convergence_tracker.json state, Agent Mail reservations) matter; an agent that thinks it's resuming when the workspace is empty will fabricate progress.
- **The Up-Front Confirmations preamble is the human-touch step.** After confirmation, the rest is mechanical. Do not skip the preamble in CI / scripted invocations — the wall-time estimate is the single most useful expectation-setter.
- **One mode per session.** If the user asks to "audit then fix", run `audit-only` first, surface the report, then dispatch a NEW `gauntlet-full` session. Mid-session mode-switching breaks the convergence tracker.

See [MODE-ROUTER.md](MODE-ROUTER.md) for how the modes compose with each other, and [TIER-TRIAGE.md](TIER-TRIAGE.md) for tier sizing.
