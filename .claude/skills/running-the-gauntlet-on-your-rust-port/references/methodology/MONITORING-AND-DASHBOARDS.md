# Monitoring and Dashboards

How a gauntlet-instrumented project exposes its state to operators (humans + agents) in real time. Pairs with [`PHASE-OUTPUT-SCHEMAS.md`](PHASE-OUTPUT-SCHEMAS.md) (machine-readable artifacts) and [`HOOKS-INTEGRATION.md`](HOOKS-INTEGRATION.md) (event-driven notifications).

The principle: every state transition the gauntlet cares about (Phase complete, round close, ratchet decision, e-process rejection, BOCPD regime change, soak finding, certification cut) emits both a **machine-readable artifact** and a **dashboard signal**. The two stay in sync because they share the same emission point.

---

## 1. The three viewer layers

### Layer A — terminal-native (no extra tooling)

```bash
# Live state of a gauntlet workspace
./scripts/gauntlet-status.sh <workspace>
```

Emits a 30-line text snapshot:
```
Gauntlet: frankensqlite__gauntlet_workspace
Run-id:   r20260522-1830-3a8c1d2
Tier:     T3
Phase:    11 (round_count 7 of >=10; clean_last_two = false)

Pillars:
  perf:        ratchet=Allow conformal_lower=0.9234 open_hypotheses=3
  conformance: ratchet=Allow conformal_lower=0.9876 open_hypotheses=1
  surface:     ratchet=Block conformal_lower=0.8901 open_hypotheses=5

Active NTM session: frankensqlite__gauntlet (12 panes, 0 stalled, 1 rate-limited)
Active rch jobs:    3 (soak-fuzz-r4, soak-miri-r4, soak-bocpd-r3)
Last commit:        2h ago — "round_6: synthesizer report"
Last failure:       45m ago — bd-1dp9.7.3 (perf regression, see <workspace>/round_7/perf_findings.json#L42)

Next action: round 8 dispatch (iteration-coordinator)
```

This is the **terminal-native dashboard**. No browser, no Grafana, no extra deps. Runs in <1 second; safe to bind to a tmux pane via `watch -n 30`.

### Layer B — Markdown-tracker (committed to git)

Per [`MEMORY-MD-CONVENTION.md`](MEMORY-MD-CONVENTION.md), `<workspace>/MEMORY.md` is the source-of-truth tracker: one line per session, ≤150 chars each, indexable. Future agents (after compaction) restore state from MEMORY.md alone.

The `<workspace>/STATUS.md` (auto-generated by `scripts/gauntlet-status.sh --markdown`) is a richer snapshot — same data as Layer A but rendered as Markdown tables + cross-links into the workspace. Refresh after every phase transition.

### Layer C — Prometheus + Grafana (optional; for long-running workspaces)

For workspaces running for 10+ days where operators want historical trending:

**Prometheus metrics** (exposed via `scripts/gauntlet-prom-exporter.sh --workspace <workspace> --port 9876`):

```
# Per-pillar conformal lower-bound (gauge; updated per round)
gauntlet_pillar_conformal_lower{pillar="perf|conformance|surface", workspace="..."}

# Per-pillar ratchet state (gauge: 1=Allow, 0=Block, -1=Quarantine, 2=Waiver)
gauntlet_pillar_ratchet_state{pillar="...", workspace="..."}

# Per-invariant e-value (gauge; updated per observation)
gauntlet_eprocess_log_e_value{invariant_id="INV-...", workspace="..."}

# Per-round new-findings count (counter)
gauntlet_round_new_findings_total{round="N", pillar="...", workspace="..."}

# Convergence state (gauge)
gauntlet_convergence_round_number{workspace="..."}
gauntlet_convergence_clean_last_two{workspace="..."}
gauntlet_convergence_open_hypothesis_count{workspace="..."}

# Soak runner state (gauge per runner)
gauntlet_soak_duration_remaining_seconds{runner="fuzz|miri|loom|crash|bocpd|adversarial", workspace="..."}
gauntlet_soak_findings_total{runner="...", severity="critical|high|medium|low", workspace="..."}
```

**Grafana dashboard JSON** (per the project's actual deployment): `assets/grafana-dashboards/gauntlet-overview.json` ships a reference dashboard with 12 panels:
1. Per-pillar conformal lower-bound (3 line charts).
2. Per-pillar ratchet state (3 status stoplights).
3. Per-invariant e-value (1 multi-series chart).
4. Per-round new-findings count (3 bar charts).
5. Convergence state (3 single-stat panels).
6. Soak runner state (1 multi-series chart with timeline).

Used during long-running soak campaigns where direct attendance is impractical.

## 2. Per-event dashboard signals

Each gauntlet state transition emits both an artifact AND a dashboard signal:

| Event | Artifact path | Layer A signal | Layer B signal | Layer C signal |
|---|---|---|---|---|
| Phase complete | `<workspace>/.gauntlet/phase<N>_complete.flag` | next-action line updates | STATUS.md regenerated | `gauntlet_phase_complete_total{phase=N}` counter+1 |
| Round close | `<workspace>/round_<N>/synthesis.md` | "clean_last_two" line updates | MEMORY.md appended | `gauntlet_convergence_clean_last_two` gauge updates |
| Ratchet decision | `<workspace>/reports/ratchet_state.json` | "ratchet=" line updates | STATUS.md regenerated | `gauntlet_pillar_ratchet_state` gauge updates |
| E-process rejection | `<workspace>/round_<N>/<pillar>_failures/<sig>/bundle.json` | "Last failure" line updates | STATUS.md + MEMORY.md appended | `gauntlet_eprocess_rejections_total` counter+1 |
| BOCPD regime change | `<workspace>/phase15_soak_bocpd/regime_changes.jsonl` | "BOCPD regime" line appears | STATUS.md regenerated | `gauntlet_bocpd_regime` gauge updates (1=Stable, 2=Improving, -1=Regressing, -2=ShiftDetected) |
| Soak finding | `<workspace>/phase15_soak_<runner>/findings/<sig>/bundle.json` | "Active rch jobs" + finding count update | STATUS.md regenerated | `gauntlet_soak_findings_total` counter+1 by severity |
| Certification cut | `<workspace>/certification_bundle/release_certificate.json` | "Certification:" status updates | STATUS.md regenerated | `gauntlet_certifying` gauge updates (1=true/0=false) |

This dual emission is enforced by [`hooks/auto-stage-bench-history.sh`](../../assets/hooks/auto-stage-bench-history.sh) and the Phase 16 `certification-bundler` subagent — every artifact write triggers a signal update.

## 3. Notification channels (per-event)

Per [`HOOKS-INTEGRATION.md`](HOOKS-INTEGRATION.md), `Stop` hooks fire when an agent ends a substantive operation. The gauntlet wires:

| Event | Notify? | Channel | Why |
|---|---|---|---|
| Phase 0..8 complete | NO | — | routine; no operator action |
| Phase 9 complete (baseline ready) | YES | Agent Mail thread `gauntlet-<run-id>-baseline-ready` | first operator decision point |
| Round close (clean) | NO | — | routine |
| Round close (non-clean after 3 rounds) | YES | Agent Mail thread `gauntlet-<run-id>-stall-warning` | Deep-review escalation candidate |
| Ratchet → Block | YES | Agent Mail thread `gauntlet-<run-id>-ratchet-block` | operator decides fix-vs-waiver |
| E-process rejection (any) | YES (CRITICAL) | Agent Mail + desktop notification | immediate action needed |
| BOCPD regime = ShiftDetected | YES (HIGH) | Agent Mail thread | regime change = potential bug |
| Soak finding (CRITICAL severity) | YES (CRITICAL) | Agent Mail + desktop + Slack (if configured) | release blocker |
| Certification cut → true | YES (HIGH) | Agent Mail thread + git tag | release-ready notification |
| Certification cut → false | YES (HIGH) | Agent Mail thread + RELEASE_BLOCKED.md | identifies blocker |

Configuration in `<workspace>/.gauntlet/notification_routes.toml`:

```toml
[channels]
agent_mail = "always"
desktop    = "critical_only"
slack      = { enabled = false, webhook_url = "", critical_only = true }
```

## 4. The `gauntlet-status.sh` script reference

```bash
#!/usr/bin/env bash
# scripts/gauntlet-status.sh — Layer A terminal snapshot
# Usage:
#   gauntlet-status.sh <workspace>            # text snapshot
#   gauntlet-status.sh <workspace> --markdown # markdown for STATUS.md
#   gauntlet-status.sh <workspace> --json     # for downstream tooling

set -euo pipefail

WORKSPACE="${1:-.}"
MODE="${2:-text}"

# Read generated Phase 11 convergence state from durable artifacts
TRACKER="$WORKSPACE/reports/convergence_tracker.json"
ROUND=$(jq -r '.round_count' "$TRACKER" 2>/dev/null || echo "?")
CLEAN=$(jq -r 'if .clean_last_two then (.required_consecutive_clean // 2) else 0 end' "$TRACKER" 2>/dev/null || echo "?")
OPEN_TOTAL=$(jq -r '.open_hypothesis_count' "$TRACKER" 2>/dev/null || echo "?")
LAST_TWO=$(jq -c '.last_two_findings' "$TRACKER" 2>/dev/null || echo "?")

# Per-pillar ratchet + conformal-lower
RATCHET_PERF=$(jq -r '.perf.decision' "$WORKSPACE/reports/ratchet_state.json" 2>/dev/null || echo "?")
RATCHET_CONFORM=$(jq -r '.conformance.decision' "$WORKSPACE/reports/ratchet_state.json" 2>/dev/null || echo "?")
RATCHET_SURF=$(jq -r '.surface.decision' "$WORKSPACE/reports/ratchet_state.json" 2>/dev/null || echo "?")

# ... etc ...

case "$MODE" in
  text)     emit_text     ;;
  markdown) emit_markdown ;;
  json)     emit_json     ;;
  *) echo "unknown mode: $MODE" >&2; exit 2 ;;
esac
```

Full implementation lives in `scripts/gauntlet-status.sh`; this excerpt shows the shape.

## 5. When dashboards lie

A dashboard is a SUMMARY. The artifacts are the SOURCE OF TRUTH. When a dashboard signal disagrees with an artifact, the artifact wins — but the disagreement itself is a bug worth investigating.

Common dashboard-lying scenarios:
- **Stale cache**: Grafana caches metric values; if the exporter crashed but Grafana didn't notice, the dashboard shows stale data. Mitigation: alert on `up{job="gauntlet-exporter"} == 0`.
- **Race**: artifact written, dashboard not yet updated. Operators querying within the 30-second refresh window see stale state. Mitigation: bookend every Layer-A snapshot with the artifact's mtime; operators see "as of <ISO>" and know to wait.
- **Schema drift**: artifact schema bumped to vN+1 but exporter still reads vN, silently dropping new fields. Mitigation: `gauntlet_exporter_schema_mismatch_total` counter; alert on increment.

The discipline: **trust the artifact; verify the dashboard against the artifact when in doubt**. Never make a Phase-12 remediation decision off a dashboard alone — read the underlying `ratchet_state.json` / `eprocess_state.json` / `bocpd_summary.json` first.
